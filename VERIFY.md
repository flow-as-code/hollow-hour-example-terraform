# VERIFY: what this approach relies on, and how we know

The Amazon Connect behaviors the hotline relies on are the same whichever
repository deploys it, and the TypeScript-first repository checked them
against live instances, most of them on its dev instance only (then in
us-west-2; it moved to us-east-1 on 2026-09-30); row S2 also ran on qa and
prod (us-east-1). Its
[VERIFY.md](https://github.com/flow-as-code/hollow-hour-example-typescript/blob/main/VERIFY.md)
is the ledger for those, with the AWS documentation, the date and the
service's answer for each. The ones this repository's design depends on:

What follows is what the Terraform-first approach adds. Status is
**docs-checked** (the documentation or the tooling's published contract
says it), **offline-checked** (shown by a plan or test here, which makes no
AWS call), **harness-checked YYYY-MM-DD: result** (shown by running the
equivalence harness, `tools/equivalence`, which plans with placeholder
credentials; the result is what it showed), **read YYYY-MM-DD** (a read-only
AWS call), **sandbox-checked YYYY-MM-DD, Region** (observed on a live apply
from this repository), or **needs sandbox** (only a live apply can show it).
No account id, instance id or ARN appears in any row.
